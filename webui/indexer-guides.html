Indexer Plugin System — Overview

NZBPostarr uses a YAML plugin system for indexer definitions. Each indexer is a single .yaml file in indexers/ . Adding a new indexer means creating a new YAML file — no Python code required.

How It Works
1
Boot — IndexerRegistry scans indexers/*.yaml , skipping files prefixed with _ . Each file is validated into an IndexerDefinition Pydantic model.
2
Config Resolution — API keys, usernames, enabled/backfill/priority flags are resolved from config.yaml at runtime via resolve_indexer_* helpers, not stored in the YAML.
3
Upload — The uploader reads the indexer's method , auth , files , and success definitions to construct the correct HTTP request (POST multipart, cURL subprocess, etc.).
4
Response — Success/duplicate detection uses text_patterns , json_path , or duplicate_patterns from the YAML. Duplicates are treated as success.
Built-in Indexers

Authentication Methods
Method Used By How It Works
query_param NZBGeek, NZB.su, NZBPlanet API key appended to URL: ?apikey=KEY

Creating a Custom Indexer

Copy _template.yaml → my_indexer.yaml and fill in the fields below. The registry auto-loads it on next restart.

Full Template Reference 
# Required
id: my_indexer                              # Unique ID (lowercase, no spaces)
name: My Indexer Name                       # Display name in UI
submit_url: https://api.example.com/submit  # API endpoint URL
method: POST                                # POST, PUT, or CURL

# Authentication
auth:
  method: query_param                       # query_param | header | form_field | curl_url | none
  api_key_param: apikey                     # Parameter name for API key
  # username_param: user                    # For indexers requiring username
  # header_name: Authorization              # For header-based auth
  # header_template: "Bearer {api_key}"     # Template for header value

# For CURL method only:
# curl_template: "https://example.com/api?user={username}&api={api_key}"

# Category mapping (upload category → indexer category code)
# NZBPostarr job categories are typically: tv, movies, misc, ...
# Singular/plural are interchangeable (movies/movie) via a fallback in the registry.
categories:
  tv: '5040'
  movie: '2040'
  anime: '5070'
  audiobook: '3030'
  ebook: '7020'
  music: '3010'
  games: '1000'
  misc: '5000'
  default: '5000'
category_param: cat                         # URL param name for category

# File upload field names
files:
  nzb: nzb                                 # Field name for NZB file
  nfo: nfo                                 # Field name for NFO (null to disable)
  # mediainfo: mediainfo                   # Optional separate mediainfo field
  nzb_mime: application/x-nzb              # MIME type

# Optional
name_param: name                            # Param for release name
extra_params:                               # Static query params always included
  t: nzbadd
extra_form_data: {}                         # Static form fields

# Success detection
success:
  # JSON path check (optional)
  json_path: response.status
  json_value: OK
  # Text patterns (checked against response body)
  text_patterns:
    - 'SUCCESS'
    - 'OK'
  # Duplicate patterns (treated as success)
  duplicate_patterns:
    - 'duplicate'
    - 'already exists'

# Behaviour
timeout: 30                                 # Request timeout in seconds
requires_nfo: false                         # Create empty NFO if missing

# UI (optional)
description: A brief description
website: https://example-indexer.com
favicon_url: https://example-indexer.com/favicon.ico
icon: globe                                 # Lucide icon name
color: '#808080'                            # Hex colour for UI & logs

Batch Upload Script (Linux) 
#!/bin/bash
nzb_folder="/home/user/nzb_submissions"
nzb_done="/home/user/nzb_submissions_complete"
myapikey="YOUR_GEEK_API_KEY"

if [ "$(ls -A $nzb_folder)" ]; then
  cd "$nzb_folder"
  for DA in *; do
    echo "Processing: ${DA}"
    curl -k -s -L -m 60 -F nzb=@"$nzb_folder/$DA" \
      "https://api.nzbgeek.info/submit?apikey=$myapikey"
    mv "$nzb_folder/$DA" "$nzb_done/$DA"
    echo "Processed: ${DA}"
  done
else
  echo "Submission Folder is Empty"
fi
NZBPostarr config: api_keys.geek: YOUR_KEY — that's all. Category, NFO, success detection are all handled automatically from geek.yaml .
I NZBs.in nzbs.in

NZBs.in uses header-based Bearer token authentication — different from most Newznab indexers. It also supports optional MediaInfo, screenshots, and NFO attachments in the same upload.

Authentication
Property Value
Submit URL https://v2.nzbs.in/api/v1/nzb/upload
Method POST (multipart/form-data)
Auth Type HTTP Header
Header Authorization: Bearer YOUR_API_TOKEN
Accept Header application/json
Search URL https://nzbs.in/search?category=&query="{poster}"
Category Mapping

NZBs.in uses string-based categories instead of numeric codes:

Content Type Category String
tv tv-shows
movie movies
anime anime
audiobook audiobooks
ebook ebooks
music music
games games
misc / default apps
Upload Fields
Field Name Required Notes
NZB file nzb required Max 20MB. MIME: application/x-nzb
Category category required String category (see above)
Release name name optional Defaults to NZB filename if omitted
NFO file nfo optional Plain text, max 2MB
MediaInfo mediainfo optional .txt file, max 2MB, standard MediaInfo format
Screenshots screenshots[] optional Comma-separated URLs (.jpg/.png), up to 10
Unique feature: NZBs.in is the only supported indexer that accepts MediaInfo and screenshot URLs as separate upload fields.
cURL Examples 
# Basic upload
curl -X POST "https://v2.nzbs.in/api/v1/nzb/upload" \
  -H "Authorization: Bearer <token>" \
  -H "Accept: application/json" \
  -F "nzb=@/path/to/release.nzb" \
  -F "name=My.Release.S01E01.1080p" \
  -F "category=tv-shows"

# Full upload with all optional fields
curl -X POST "https://v2.nzbs.in/api/v1/nzb/upload" \
  -H "Authorization: Bearer <token>" \
  -H "Accept: application/json" \
  -F "nzb=@/path/to/release.nzb" \
  -F "name=My.Release.S01E01.1080p" \
  -F "category=tv-shows" \
  -F "screenshots[]=https://img.example.com/shot1.jpg,https://img.example.com/shot2.jpg" \
  -F "mediainfo=@/path/to/mediainfo.txt" \
  -F "nfo=@/path/to/release.nfo"
Python Example 
import requests

response = requests.post(
    url="https://v2.nzbs.in/api/v1/nzb/upload",
    headers={
        "Authorization": "Bearer YOUR_API_TOKEN",
        "Accept": "application/json",
    },
    files={
        "nzb": open("/path/to/release.nzb", "rb"),
        "mediainfo": open("/path/to/mediainfo.txt", "rb"),  # optional
        "nfo": open("/path/to/release.nfo", "rb"),           # optional
    },
    data={
        "category": "movies",
        "name": "My.Movie.2024.1080p.BluRay-GROUP",
    },
)

result = response.json()
if result.get("success"):
    print("Upload successful:", result["success"])
else:
    print("Upload failed:", result)
Success Detection
Check Pattern
JSON path success field in response JSON
Text patterns "success": , "ok"
Duplicate "duplicate"
Important notes:
• Uploads are not counted towards your API rate limits.
• Processing may take a few minutes after upload — don't re-upload.
• Add a 2-second delay between consecutive uploads to avoid abuse protection.

S NZB.su / NZB.life api.nzb.life
CRITICAL — The URL situation: NZB.su has two domains . Only https://api.nzb.life/api works for API calls. Using https://nzb.su/api returns Missing parameter on every request. If your app asks for a host/base URL and appends /api automatically, use https://api.nzb.life/ as the host. If you get error 200 on everything, you're hitting the wrong domain.
Authentication
Property Value
Base URL https://api.nzb.life/api
App Base Host https://api.nzb.life/ if the client appends /api automatically
API Style GET for search/read endpoints, POST multipart/form-data for uploads
Auth Type Query parameter
Auth Param ?apikey=YOUR_KEY (32-char hex)
API Key Location nzb.su → Profile → API Key
Rate Limiting Cloudflare — wait 1-2s between requests; HTTP 429 with Retry-After: 5 on burst
NZB Upload — t=nzbadd

This is the upload function. All parameters go in the URL query string , while the NZB file goes in the multipart POST body :

Param Location Required Description
apikey URL query required Your API key
t URL query required Must be nzbadd
cat URL query recommended Newznab category ID (e.g. 5040 )
name URL query recommended Release name for display
file POST body required The .nzb file. Field name MUST be file
nfo POST body optional NFO file (text/plain)
Category matters: NZB.su will accept uploads without a valid cat , but they can appear as No category (and may show 0 MB until processed). NZBPostarr sets cat automatically from the job's category (tv/movies/misc) using your indexer YAML mapping.
Common mistakes that cause "Missing parameter":
• Using nzb.su/api instead of api.nzb.life/api
• Putting cat / name in POST body instead of URL query
• Using field name nzb instead of file
• Forgetting t=nzbadd in the query string
cURL Upload Example 
curl -X POST \
  "https://api.nzb.life/api?apikey=YOUR_KEY&t=nzbadd&cat=5040&name=My.Release.1080p-GROUP" \
    -F "file=@/path/to/My.Release.1080p-GROUP.nzb;type=application/x-nzb" \
    -F "nfo=@/path/to/My.Release.1080p-GROUP.nfo;type=text/plain"
Python Upload Example 
import requests

response = requests.post(
    url="https://api.nzb.life/api",
    params={
        "apikey": "YOUR_API_KEY",
        "t": "nzbadd",
        "cat": "5040",
        "name": "My.Release.S01E01.1080p.WEB-DL-GROUP"
    },
    files={
        "file": (
            "My.Release.S01E01.1080p.WEB-DL-GROUP.nzb",
            open("release.nzb", "rb"),
            "application/x-nzb",
        ),
        # Optional NFO upload
        "nfo": (
            "My.Release.S01E01.1080p.WEB-DL-GROUP.nfo",
            open("release.nfo", "rb"),
            "text/plain",
        ),
    },
    timeout=30
)

if "<success" in response.text.lower():
    print("Upload successful!")
else:
    print(f"Upload failed: {response.text}")

O OMGWTFNZBs omgwtfnzbs.org

OMG is unique among indexers — it uses cURL-based submission with both username and API key in the query string, and its own category system. It also requires an NFO for every upload.

Authentication
Property Value
Submit URL https://omgwtfnzbs.org/api-upload
Method CURL (multipart form POST via cURL subprocess)
Auth Type URL parameters: ?user=USERNAME&api=API_KEY
Requires Username Yes — both api_keys.omg and usernames.omg in config
Search URL https://omgwtfnzbs.org/browse.php?search="{poster}"
Why cURL? OMG has specific SSL/form requirements that standard Python requests doesn't handle reliably. NZBPostarr shells out to cURL for this indexer.
