What is NZBPostarr?

NZBPostarr is a self-hosted, automated Usenet upload manager. It takes media files from your filesystem, packages them with RAR + PAR2 parity, posts them to Usenet via NNTP, generates NZB files, and submits those NZBs to one or more indexer sites - all from a single command or a clean web dashboard.

Core Features

  • • Multi-indexer uploads (NZBGeek, NZB.Life, OMG, NZBPlanet, NZBs.in, NZBSlug)
  • • Automatic RAR splitting + PAR2 parity generation
  • • NNTP posting via Nyuu with multi-connection support
  • • Intelligent duplicate detection & backfill
  • • Season pack awareness with episode-first ordering
  • • Dynamic category detection from folder paths
  • • MediaInfo generation and NFO attachment

Platform Features

  • • Real-time Web UI with job progress, console, and stats
  • • Headless CLI mode (no UI required)
  • • Folder monitoring with auto-trigger on new content
  • • SQLite database for upload history & deduplication
  • • Background scheduler (APScheduler) for periodic tasks
  • • Process reaper for orphaned tool cleanup
  • • First-run setup wizard for fresh deployments
Tech Stack: Python 3.12+, FastAPI, SQLAlchemy, Pydantic v2, Vue.js 3, Tailwind CSS. External tools: nyuu , parpar , rar .

Quick Start (Interactive Setup)

The recommended way to install NZBPostarr is to use the built-in interactive setup wizard. It automates almost everything - environment creation, dependency installation, and configuration.

One-Command Installation 
python main.py --setup
What this command does:
  • Creates a virtual environment ( .venv )
  • Installs all Python requirements ( pip install )
  • Attempts to auto-install nyuu , parpar , and rar
  • Guides you through creating your config.yaml
  • Performs a smoke test to ensure things work
Platform Specific Notes

Linux & WSL (Recommended)

The wizard is fully automated on Linux/WSL. It will attempt to install system dependencies via apt-get and binary downloads.

Note: You may be prompted for your sudo password to install system tools.

Windows (Native)

The wizard handles the venv and config, but you must manually install external tools or use npm : 

npm install -g nyuu parpar

Ensure nyuu , parpar , and rar are in your System PATH.

Prerequisites (Manual)

Before running the setup command, ensure you have these basics:

  • Python 3.12+ installed and added to PATH
  • Node.js 18+ (only if you want to use npm for tools)
  • Git (or just download the project source)
Configuration (config.yaml)

The main config lives at the project root as config.yaml . Copy config.defaults.yaml as your starting template. All settings are validated by Pydantic at startup.

Folder Paths 
base_folder: '/path/to/usenet'

folder_paths:
  - path: '${base_folder}/Movies'
    category: movies
  - path: '${base_folder}/TV'
    category: tv
  - path: '${base_folder}/Misc'
    category: misc
  - path: '/srv/downloads/qbittorrent'
    category: external       # requires manual category selection in UI
Supported categories: movies , tv , misc , anime , audiobooks , ebooks , music , games , external .
Upload Identity 
poster_name: 'Anonymous'
poster_email: 'anonymous@example.com'
include_readme: true              # Attach readme.txt to every upload
alt_bins:
  - 'alt.binaries.misc'           # Newsgroup pool (randomized)

NNTP Server Configuration

NNTP servers are defined in the nntp_servers array. The first server is the primary upload target. 

nntp_servers:
  - name: 'Primary'
    host: 'news.example.com'
    user: 'YOUR_USERNAME'
    pass: 'YOUR_PASSWORD'
    port: 563
    ssl: true
    enabled: true
    max_connections: 20
    backbone: ['Hosted']
Field Type Description
name string Display name for this server
host string NNTP server hostname
user / pass string Authentication credentials
port int 563 (SSL) or 119 (plain)
ssl bool Use SSL/TLS encryption
max_connections int Simultaneous connections (start with 20)
backbone list Backbone provider info (display only)
Tip: Most providers allow 20–50 connections. Higher counts improve speed but may cause throttling.

Upload Pipeline

Each item goes through this multi-stage pipeline:

1
Discovery & Sorting

Items found from configured folder. TV sorted by show name, episodes before packs. Size limits and skip patterns evaluated.

2
Duplicate Check

Checked against SQLite for all enabled indexers. Backfill mode fills indexers that don't have the item yet.

3
Pre-Processing (RAR + PAR2)

Copied to temp, split into RAR volumes, PAR2 generated via ParPar. MediaInfo NFO produced for video.

4
NNTP Upload (Nyuu)

Nyuu posts RAR+PAR2 to Usenet. Live progress blended from read/post counters. NZB generated on completion.

5
Indexer Submission

NZB submitted to each enabled indexer via their plugin API. Success/duplicate responses auto-detected.

6
Cleanup

Temp files removed, NZB archived to internal/nzbs/ . Stats recorded.

Folder Monitor (Auto-Upload)

Event-driven daemon via Watchdog . Watches folders for new content, auto-triggers uploads after files settle. 

folder_paths:
  - path: '/path/to/TV'
    category: tv
    monitor: true        # enables auto-upload
Behaviour Description
Settle Time 30 seconds after last filesystem event before triggering
Baseline Existing items at startup are ignored
Top-Level Only Only new top-level items trigger; nested changes update settle timer
Category Uses the folder_paths category; external is never monitored
Note: Folder monitor only works in WebUI mode (not headless). Uses native OS filesystem events.

Environment Variables

All settings can be overridden via env vars with the NZBP_ prefix. Nested keys use double underscores.

Environment Variable Equivalent config.yaml
NZBP_LOG_LEVEL=DEBUG log_level: DEBUG
NZBP_PORT=9000 port: 9000
NZBP_API_KEYS__GEEK=abc api_keys: { geek: abc }
NZBP_USERNAMES__OMG=user usernames: { omg: user }
NZBP_ENABLE_GEEK=true enable_geek: true
NZBP_TEST_RUN=true test_run: true
.env file: A .env file in the project root is auto-loaded. Recommended for server credentials.
Troubleshooting & FAQ

"Unable to open database file"

Give the service account ownership of the application data directory:

sudo chown -R nzbpostarr:nzbpostarr /opt/nzbpostarr/data
sudo chmod -R u+rwX,go-rwx /opt/nzbpostarr/data

"Missing required tools: nyuu, parpar, rar"

npm install -g nyuu parpar
apt install rar   # or your OS equivalent

"Database is locked"

Auto-retry logic (3 attempts, exponential backoff) handles most cases. If persistent: ensure only one instance is running and avoid NFS mounts for SQLite.

Uploads stuck at 90-99%

Normal - Nyuu blends read (70%) + posted (30%) progress. The last percent is server acknowledgment. Caps at 99% until fully complete.

Orphaned nyuu/rar processes

The Process Reaper runs every 10 minutes (+ on boot). Kills tool processes >6h old that don't belong to active jobs.

How do I add a new indexer?

Copy indexers/_template.yaml , fill in API details, add credentials to config.yaml , restart. Auto-loaded on boot.

Can I run without the WebUI?

Yes - --headless mode. Delete webui/ entirely. All features work from CLI.
